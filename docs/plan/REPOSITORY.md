# Repository plan

One repository (`Vertex-Systems-Network/zynoa`) holds every app. Website, dashboard, desktop and mobile share the design system, API contracts and tokens; separate repos would mean every change in four places and drifting versions.

## Layout

```
zynoa/
  apps/
    site/           Marketing website (Next.js)
    web/            Dashboard (Next.js) — authenticated app + end-customer pages
    desktop/        Windows/macOS shell (Tauri 2) — Rust in src-tauri/
    mobile/         iOS/Android (Expo)
    api/            Fastify HTTP API + SSE
    worker/         Temporal workers (TypeScript)
    media-worker/   Python Temporal activities (FFmpeg)
  packages/
    tokens/         Design tokens (CSS, Tailwind, shadcn bridge, RN theme)
    ui/             Shared React components (consumes tokens)
    contracts/      Zod schemas, DTOs, error codes — shared by every app
    db/ authz/ model-gateway/ agents/ sandbox/ integrations/
    workflow-engine/ systems-runtime/ billing/ config/ test-utils/
  docs/
    plan/           Current plan (start here)
    spec/           Product specification
    design/         Figma references
    decisions/      ADRs
    plans/          Per-phase plans and exit reports written by agents
  infra/            docker/, terraform/
  .github/          Workflows, CODEOWNERS, templates
  (ANPOS)           AGENTS.md, .ai/, config/, schemas/, scripts/, tests/, *.md protocol files
```

Package detail for `packages/*`: `docs/spec/ENGINEERING-RULES.md` §3. The only layout change from the spec is splitting `apps/site` out of `apps/web`, and adding `apps/desktop`, `apps/mobile` and `packages/tokens`.

## Branches

- `main` is always deployable; no direct pushes once GitHub Rules are applied (ANPOS step "Apply Recommended GitHub Rules").
- One branch per work unit: `feat/WU-P0-01-scaffold`, `fix/…`, `chore/…`. Parallel agents each get their own branch or git worktree.
- Merge only when CI is green, a separate review agent has passed it, and a human approves.
- No long-lived `develop` branch; unfinished features ship behind feature flags (`docs/spec/ENGINEERING-RULES.md` §4).

## CI (GitHub Actions)

`.github/workflows/ci.yml` runs on every PR to `main`, on pushes to `main` and in the merge queue. Each job is a required check (`.github/rulesets/main-protection.json`):

| Check | What it runs |
|---|---|
| `build-test` | `pnpm install --frozen-lockfile`, Prettier check, `turbo run lint typecheck test build` (Turborepo cache restored between runs), `turbo run db:check` (migration check; active once `packages/db` defines it), design-token freshness |
| `secret-scan` | gitleaks over the full git history (binary checksum-verified) |
| `sast` | Semgrep `p/default` over `apps/` and `packages/` |
| `dependency-scan` | Trivy filesystem scan of lockfiles, HIGH/CRITICAL fixable vulnerabilities |
| `repository-integrity` | ANPOS governance validators and tests (`repository-quality.yml`) |

- Turborepo runs only what changed; a change in `packages/tokens`, `packages/ui` or `packages/contracts` re-tests every dependant.
- Container image build/scan joins `build-test` when the first Dockerfile lands (WU-P0-06).
- Preview deploys for `site` and `web` arrive with those apps (WU-P0-07/08).
- Desktop builds (Windows + macOS runners) only on `desktop@*` tags; mobile builds only on `mobile@*` tags.
- Dependabot (`.github/dependabot.yml`): weekly, grouped GitHub Actions updates and grouped dev-tooling npm updates for the whole pnpm workspace.

## Releases

| App | When | How |
|---|---|---|
| Website | Every merge to `main` | Vercel / Cloudflare auto-deploy |
| Dashboard | Staging first, production after approval | Tag `web@x.y.z` |
| API + workers | With the dashboard | Container deploy, tag `api@x.y.z` |
| Desktop | On tag `desktop@x.y.z` | CI builds, signs, publishes to the updater |
| Mobile | On tag `mobile@x.y.z` | EAS Build → TestFlight / Play internal → stores; JS-only fixes via EAS Update |

Each app versions independently; Changesets writes the changelogs. The desktop shell loads the hosted dashboard, so dashboard features reach desktop users without a desktop release.

## Secrets and access

- No keys or passwords in the repo. GitHub Environments (`staging`, `production`) + cloud secret manager.
- Signing certificates (Apple, Windows) live only in CI secrets.
- CODEOWNERS (generated by ANPOS bootstrap) protects control-plane paths; add `packages/db`, `packages/authz`, `packages/billing` owners in WU-P0-01.
