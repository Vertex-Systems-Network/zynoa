# 04 — Data Model

PostgreSQL 16. Definitions below are **normative**: names, types and constraints should be implemented as written (in Drizzle schema files under `packages/db/schema/<module>.ts`). Columns not listed may be added if documented.

## 0. Conventions

- Every table has `id uuid primary key` (UUIDv7 generated by app), `created_at timestamptz not null default now()`, `updated_at timestamptz not null default now()` (trigger-maintained). These are **omitted below** to save space.
- **Tenant tables** (marked 🔒) have `workspace_id uuid not null references workspaces(id) on delete cascade`, an index leading with `workspace_id`, and the RLS policy from §15. **Exceptions (must survive workspace deletion):** in `audit_events` (nullable — user-level events have none), `ledger_entries`, `billing_invoices` and `payments`, `workspace_id` (and `ledger_entries.credit_account_id`) are **plain uuid columns without foreign keys**, so deleting a workspace never fails or cascades into them; the erasure job pseudonymises them instead. Deleted workspaces additionally keep a tombstone `workspaces` row (`status='deleted'`, name/slug scrubbed) for billing history.
- **Optimistic concurrency:** tables edited concurrently by humans carry `version int not null default 1`, incremented on every update; clients send `If-Match: "<version>"` (file 12 §1). Applies to: `projects`, `requirements`, `milestones`, `tasks`, `comments`, `discussions`, `assets`, `design_frames`, `workflows`, `system_records` (already has `version`), `system_instances`. (Do **not** compare `updated_at`: Postgres stores microseconds, JS dates milliseconds.)
- **Extensions:** Phase 0 migration creates `citext` and `vector` (pgvector ≥ 0.8); Phase 6 adds `btree_gist` (bookings exclusion constraint). Constraints Drizzle cannot express (`EXCLUDE`, partial unique indexes, RLS policies, `SECURITY DEFINER` functions) live in hand-written SQL migrations.
- **Nullable keys in unique constraints** use `unique nulls not distinct (...)` (Postgres 15+).
- `created_by uuid` references `users(id)` where shown as `created_by`.
- Soft delete: tables marked ♻ have `deleted_at timestamptz null`; repositories filter `deleted_at is null` by default; hard deletion by retention job after 30 days.
- Enums are Postgres `text` + `CHECK` constraint (easier migrations than native enums). Listed as `status text check (status in (...))`.
- JSON columns are `jsonb`, always validated by a Zod schema named in the comment.
- Money: `amount_minor bigint` + `currency char(3)`. Credits: `bigint` micro-credits (1 credit = 1,000,000).
- Phase in which each table first appears is shown as **[P1]** etc.

Better Auth owns the core auth models. Use **its** models, renamed via its schema config (`modelName` / `fields`), and add our extra columns via `additionalFields`. Configure `advanced.database.generateId` to return UUIDv7. **Invariant (enforced in service + DB trigger):** a `personal` workspace has exactly one `memberships` row, whose user is `personal_for_user_id`, with role `owner`; `invitations`, `teams`, `team_members` and `project_members` with principal ≠ owner are rejected for personal workspaces.

## 15. Row-Level Security (defence in depth)

Applied to every 🔒 table:

```sql
alter table <t> enable row level security;
alter table <t> force row level security;
create policy tenant_isolation on <t>
  using (workspace_id = nullif(current_setting('app.workspace_id', true), '')::uuid)
  with check (workspace_id = nullif(current_setting('app.workspace_id', true), '')::uuid);
```
(`nullif(…, '')` is required: on pooled connections a previously `SET LOCAL` setting reads back as `''`, and `''::uuid` throws.)

**User-level audit events** (no workspace):
```sql
create policy user_events on audit_events for insert
  with check (workspace_id is null and actor_id = nullif(current_setting('app.user_id', true), '')::uuid);
```

**Cross-workspace reads by the user themself** (workspace switcher, `GET /me`, inbox across workspaces):
```sql
create policy own_rows on memberships for select
  using (user_id = nullif(current_setting('app.user_id', true), '')::uuid);
create policy own_rows on notifications for select
  using (user_id = nullif(current_setting('app.user_id', true), '')::uuid);
```

**Token resolution before the workspace is known** (invitation accept, guest share links, public System pages): `SECURITY DEFINER` functions owned by `vsn_platform` that take a token hash and return only `(workspace_id, target ids, expiry)`:
`resolve_invitation(token_hash)`, `resolve_share_link(token_hash)`, `resolve_public_site(slug)`, `resolve_public_token(kind, token_hash)`. The service then sets `app.workspace_id` and continues under normal RLS.

- The application DB role is **not** a superuser and does not have `BYPASSRLS`.
- A separate `vsn_platform` role with `BYPASSRLS` is used only by: migrations, billing reconciliation and monthly grants, retention/erasure jobs, `MoveProjectWorkflow`, the `OpsService` (operator metadata reads and credit adjustments, Phase 1+), and operator break-glass tooling. Every use is audited.
- Public end-customer endpoints use a **public-access service** that resolves `system_instance → workspace_id` from the slug/token, then sets `app.workspace_id` and restricts queries to the allowed public operations.
- Project-level access (membership) is enforced in the service layer (file 05), not RLS.

## 16. Required indexes (beyond PK/unique)

- Every 🔒 table: `(workspace_id)` or a composite starting with it.
- `tasks (workspace_id, project_id, status, board_position)`; `tasks (workspace_id, owner_user_id) where deleted_at is null`.
- `agent_runs (workspace_id, project_id, status)`; `run_events (workspace_id, seq)`, `(job_run_id, seq)`, `(agent_run_id, seq)`.
- `model_calls (workspace_id, created_at desc)`; `usage_events (workspace_id, occurred_at)` — partition `usage_events`, `model_calls`, `run_events`, `audit_events` **monthly** by `created_at`/`occurred_at` from Phase 7. Partitioned tables need the partition key in the primary key and every unique constraint: idempotency uniqueness for `model_calls` then moves to the `idempotency_keys` table (or include `created_at` in the key).
- `document_chunks` HNSW on `embedding`, GIN on `tsv`, btree `(workspace_id, scope, project_id)`, btree `(workspace_id, owner_user_id)`. Vector queries filter by `workspace_id` in SQL; with HNSW this filter is applied after the index scan, so set `SET LOCAL hnsw.iterative_scan = relaxed_order` (pgvector ≥ 0.8) and use exact (sequential) search when a workspace has < 20,000 chunks.
- `bookings (workspace_id, resource_id, starts_at)`; `messages (workspace_id, contact_id, created_at desc)`.
- `notifications (user_id, read_at nulls first, created_at desc)`.
